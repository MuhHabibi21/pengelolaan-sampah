🎯 TUJUAN & SASARAN SISTEM

1. Digitalisasi Bank Sampah:

Memberikan insentif circular economy kepada warga berupa saldo rupiah dan poin reward saat menyetorkan sampah terpilah.

2. Transparansi Pengaduan Publik:

Mempermudah warga melaporkan tumpukan sampah liar dengan bukti foto autentik dan validasi berat sampah.

3. Efisiensi Pengelolaan Kota:

Membantu admin memantau timbulan sampah per wilayah, validasi transaksi, dan pengaturan fasilitas pengolahan akhir.

Hak Akses Halaman 03

Matriks Peran: Warga vs Administrator

👤

ROLE WARGA (USER)

  • ✓ Registrasi Akun Warga Baru mandiri
  • ✓ Login Akun Warga dengan JWT Cookie aman
  • ✓ Dashboard Ringkasan Laporan, Berat & Poin
  • ✓ Membuat Pengaduan Sampah + Upload Foto (1:1)
  • ✓ Transaksi Setor Sampah + Kalkulasi Otomatis
  • ✓ Mengubah Profil & Ganti Kata Sandi Akun
🛡️

ROLE ADMINISTRATOR (ADMIN)

  • ✓ Dashboard Ikhtisar Statistik Sampah Kota
  • ✓ Validasi & Verifikasi Transaksi (Selesai/Tolak)
  • ✓ Monitoring & Verifikasi Seluruh Laporan Masuk
  • ✓ Kelola Pengguna (Ubah Role Warga ⇄ Admin)
  • ✓ Kelola Master Kategori Sampah & Master Wilayah
  • ✓ Kelola Fasilitas Daur Ulang (Relasi N:N)

Arsitektur Data Halaman 11

Struktur Database & Relasi Prisma

📊 DAFTAR RELASI ENTITAS

• One-to-One (1:1): LaporanSampah ↔ FotoSampah (Tiap laporan terikat 1 bukti foto via FK laporanId).

• One-to-Many (1:N): User → LaporanSampah & User → TransaksiSampah.

• One-to-Many (1:N): JenisSampah / Wilayah → Laporan & Transaksi.

• Many-to-Many (N:N): Fasilitas ↔ JenisSampah (Fasilitas menampung banyak jenis, jenis sampah diterima di banyak fasilitas).

🛡️ KEAMANAN & INTEGRITAS DATA

• Enkripsi Bcrypt: Password di-hash 10 rounds sebelum disimpan ke database.

• JWT Session: Token disimpan di HTTP-Only cookie mencegah eksploitasi XSS.

• Validasi Zod: Memastikan berat > 0 kg, NIK 16 digit, dan format email valid.

• Prisma Transaction: Menjamin integritas data saat menyimpan laporan dan file upload.
